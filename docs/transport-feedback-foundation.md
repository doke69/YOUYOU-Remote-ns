# Transport-wide 反馈基础模块（未接入串流）

`include/transport_feedback.hpp` 和 `source/transport_feedback.cpp` 是独立、无网络副作用的协议辅助代码。未加入应用构建目标、未声明 SDP 能力、未改变 v72 安装包。仅完成 ARM64 编译和静态审核，没有运行测试套件或真机互通验证。

另有 `transport_feedback_negotiation.hpp/.cpp` 检查现有 libdatachannel 的已解析媒体能力，单独归档，尚未接入主程序。可选早期时间元数据和全局 SRTCP 路由修正也只完成库侧构建，不能把各阶段静态库混装成应用。

## 资料与适用格式

使用旧式 transport-wide 扩展及 FMT15 RTPFB 格式作为互通研究基础；它来自已归档草案，**不是最终 RFC 8888 CCFB 格式**。扩展解析支持 RFC 8285 的一字节、两字节头。没有直接移植 Pion/WebRTC 源码或引入它们的运行依赖。

- [transport-wide 草案 -01](https://datatracker.ietf.org/doc/html/draft-holmer-rmcat-transport-wide-cc-extensions-01)：反馈布局和时间刻度。
- [RFC 8285](https://www.rfc-editor.org/rfc/rfc8285.html)：RTP 扩展边界与 ID。
- [Pion RTCP 实现](https://github.com/pion/rtcp/blob/main/transport_layer_cc.go)：独立实现对照。

## 当前模块

`readTransportSequence` 只读取调用方提供的已协商 ID，不猜 ID、不把 RTP 原序号当传输序号。返回找到、缺失、不支持的 profile 或格式错误；检查扩展边界、RTP 填充、重复 ID 和准确的两字节载荷。暂不支持 transport-wide v2 可变长度请求字段。

`encodeFeedback` 接受连续传输序号对应的可选到包时间，由调用方管理序号扩展、反馈窗口和计数。内部没有线程、计时器、连接状态或永久丢包判定。它支持负到达增量及量化误差反馈，过大时间间隔返回需分包的位置；全缺失区间需明确提供同一时钟的参考时间。报文受 512 状态和 1200 字节上限约束，使用两位状态向量。RLE 压缩暂未实现，但不影响该种合法向量格式的表达。

编码失败不会返回可发送的半包；返回成功仅表示本地格式已生成，不是远端确认。零填充与 RTCP padding 位/尾字节匹配；序号及反馈计数的回绕由调用方承担。

### 固定容量到包窗口

新增 `ArrivalWindow`：4096 槽固定数组，记录时不分配堆内存。每个槽保留扩展后的传输序号和首次观察时间，序号标签防止回绕复用时误读旧数据。支持正常 16 位回绕、窗口内乱序、启动阶段向前补入旧包以及重复检测；恰好相差半个序号空间时拒绝猜测。

缓存满、时间无效、序号歧义和过旧分别返回明确状态，失败不改变窗口。`snapshot` 生成独立、最多 512 状态的快照，不消费数据；`retireBefore` 由协调器显式调用，不能在发送失败后提前推进。全部调用应由一个线程拥有或同一外部锁保护，数组应在开始串流前在堆上分配，避免占用小线程栈。

**退休边界不等同于最近反馈游标**：协调器保留乱序回看区间，跟踪哪些到包已报告；这样可在尚未退休的旧区间补报迟到包，重叠反馈中不重复报告已接收项。这个窗口本身不决定退休时机、乱序等待时间、会话重启或发送策略，不能称整个反馈接收链已完成。

### 反馈事务协调器

新增 `FeedbackCoordinator`：统一准备报文、成功提交后记账、失败保留原包、迟到补报、显式重置与缓存退休。时序参数必须由上层提供，不默认猜一套网络参数。票据跨重置不复用；发送接口接受不等于远端确认收到。协调器只提供协议状态管理，尚无 SRTCP 发送与 RTCP 开销预算，也未接入原应用。

## 接入前必须完成

1. **输入与互通验证**：截断扩展、CSRC、两种扩展格式、重复 ID、符号数量、时间回绕、量化边界、长间隔分包、MTU 以及独立解析器互通。当前未运行这些验证，不能发布“TWCC 已完成”。
2. **真实到包时间**：在收包早期记录稳定时钟，并与消息所有权一起传递，避免把组帧、认证或调度排队时间当成网络到达抖动；认证失败的包不能进入反馈。
3. **全传输窗口**：在合适的统一位置覆盖协商使用同一编号空间的音频、视频和 RTX。只看 PT96 会把其他包误报缺失。需有界乱序缓存、序号回绕及重启处理，不能按缺失状态直接宣称网络永久丢包。
4. **反馈调度**：事务协调器、共享字节预算及带退避的轮询发送器已独立编译，但尚未接入应用调度器和既有 RTCP 路径。状态/反馈计数只在适当的成功发送条件下提交。缺包反馈、恢复和拥塞控制分别负责，不把此模块当解码恢复器。
5. **协商与安全发送**：原始允许字段投影、扩展重复检查、会话级继承与认证后统一观察器已单独编译；尚未执行新 offer。全局媒体回调改走 sendMedia、弱引用连接及明确发送失败的库侧修正已编译，但还需与发送预算及主程序一起集成；不裸发 UDP 或借 DTLS 文本通道冒充 RTCP。
6. **可回退验证**：先用单独候选，确认主机真的发扩展并采用反馈；比较实际吞吐、帧内突发和卡顿。未协商则保持现有策略，不虚报启用。

此前 APK 中发现 transport-cc 能力构造路径，仍不能证明当前电脑端对这个提议有响应。50 Mbps 目标尚未达成；该模块只是补齐反馈链的必要步骤之一。

## 原始协商输入与认证后观察器（离线阶段）

后续集成入口应使用 `inspectNegotiationSdp`，直接接收对应最终 offer/answer 原始文本；不能先生成一次解析后的 SDP 再检查，因为重复定义可能已丢失。它有 256 KiB 输入、4 KiB 单行、16 媒体及每节 64 条扩展上限，只复制媒体行、MID、方向、RTP 编码/反馈与扩展允许字段；候选、密码、证书等不进入临时能力投影，也不输出原始 SDP。

按 [RFC 8285 第 5、7 节](https://www.rfc-editor.org/rfc/rfc8285.html#section-5) 拒绝同一范围重复 ID、相同 URI/属性重复声明、会话和媒体级混用。纯会话级扩展继承到媒体，方向也显式继承；不修改真实 PeerConnection。仅接受最终可用 1–255 ID，暂不支持扩展范围的备选提议。`inspectNegotiation` 低层重载仅检查已解析字段，不能单独用于开启功能。当前仍限定调用方已确认的一条 bundled transport，不是任意 SDP 的完整协商引擎。

`TransportFeedbackObserver` 应在 SRTP 认证完成后、各 Track 分流及 RTX 解封装之前作为一个全局处理器挂载，音频、视频、RTX 共享窗口。接收回调不发送报文、不复制媒体载荷、不改变消息集合；没有早期时间戳时记缺失计数，不用当前时间冒充到包时间。它的独立归档使用 `UU_RECEIVE_TIMESTAMPS=1`，必须与整个应用和最新依赖库保持同一 Message 布局；历史 OFF 库或早期 ON 库不能混用。

新增 `FeedbackBudget` 由调用方明确给出每秒字节数、突发容量及初始信用，计入调用方指定的 SRTCP/网络开销。它不是带宽估计器，也不能单独限制现有 RR/NACK 的总开销。尝试发送即扣预算，提交失败不退还信用，避免故障时无界重试；协调器仅在发送成功后推进。

## 有预算的轮询发送器（仍未接入）

`SharedRtcpBudget` 为同一传输的反馈生产者提供互斥保护和分类记账，可由调用方为接收报告/补包预留信用，TWCC/其他低优先级反馈不能使用这部分；零预留意味着调用方明确关闭该保护。既有 RR/NACK 尚未接到这个入口，不能称总 RTCP 开销已受控。

`FeedbackSender` 由外部调度器轮询，不创建线程、计时器或套接字。发送在窗口锁和预算锁之外进行；失败保留原票据与内容，指数退避有上限，重试按实际字节扣费。过期、连续失败达到上限、时间倒退或提交被拒绝时停止该实例和观察器，不停止媒体转发；完整拆卸与原策略回退仍需应用生命周期集成。发送回调必须短且不阻塞，只能在对应连接上走认证的 SRTCP；返回成功表示提交被接受，不是主机确认。时间参数使用调用方的单一稳定时钟，不能拿阻塞回调后的实际时间冒充轮询时刻。

静态审阅发现当前依赖 `Media::reciprocate` 明确移除 `rtcp-rsize`，因此不能默认允许发送裸 RTPFB。轮询发送器改为 **RR（零报告块）+ SDES CNAME + TWCC** 复合 RTCP，先为前缀预留 MTU、再准备反馈，最终 RTCP 最多 1200 字节，额外安全/网络开销另计；原有常规接收报告统计和发送计划仍保留。CNAME 必须由同一 RTP 会话提供并保持一致，不能随意另造标识。没有开启 reduced-size 能力。

依据：[RFC 3550 第 6.1 节](https://www.rfc-editor.org/rfc/rfc3550.html#section-6.1)、[RFC 5506 第 5 节](https://www.rfc-editor.org/rfc/rfc5506.html#section-5)。这些是编译和静态检查结果，尚未进行输入边界、独立解析器、发送失败或真实主机互通验证；不代表 50 Mbps 卡顿改善。

## 编译开关与连接代际附件（未挂载）

`UU_TWCC_FOUNDATION` 与 `UU_TWCC_SEND_EXPERIMENT` 均默认关闭。前者仅添加独立、默认不构建的静态库目标，要求统一开启时间元数据；后者仅允许明确配置的 `startSending`，不自动声明 SDP 或发送。主程序目前没有链接或调用这些辅助模块。

`FeedbackAttachment` 将一个已校验的最终协商与一代连接绑定：默认只观察；请求发送后才从全局认证媒体入口保存一次回调，构造 Control 消息走现有 SRTCP 路径。回调与 endpoint 均不跨连接复用，停止等待短提交结束并释放回调，故障不改原媒体消息。应用还必须在重新协商、ICE restart、断线前 stop/detach，这些调用点目前未接入。

当前 `RtcpReceivingSession` 把接收源 SSRC 也用于发送报告，未建立本机 CNAME，不能直接当新增反馈的身份。需要先梳理音视频、RR/NACK/PLI/REMB 与 BUNDLE 的身份一致性，再接入新反馈；不据此宣称找到了 50 Mbps 卡顿根因。详见离线目录 attachment/REVIEW.md。

## Client 的纯观察分支（默认关闭，未生成安装包）

新增 `UU_TWCC_OBSERVE_CLIENT` 默认关闭，要求 FOUNDATION。明确开启时才把辅助库连到 Client 构建配置；当前仅编译对象，没有链接最终程序。该分支不新增 offer 能力、不调用 startSending，不发送反馈。

异步信令间保存 `NegotiationCapabilities` 的有界能力投影，重复检查在规范化前执行，构造对象不保留原始 SDP、ICE 凭据、候选或指纹。匹配当前 Peer 的最终能力及 Stable 状态后才观察；新连接、远端重协商/ICE restart、断开前停止分离。已有全局处理器则保守跳过，不替换。

当前 offer 没有 TWCC 能力时应记录未协商，不猜 ID 或为了统计擅自改 offer。观察停止仅记录数字计数；其固定窗口满不是网络丢包。详情及现有 RR/NACK/PLI/REMB 身份表见离线目录 identity-audit/REVIEW.md。关键帧恢复请求也已纳入预算预留分类，但没有改变任何现有 Track 发包。

## 原始 BUNDLE 证明与默认关闭构建复核

能力规范化不能代替传输协商：底层序列化会自动生成 BUNDLE/rtcp-mux。现已在原始输入阶段单独保存单传输证明位，检查唯一组及 MID、全部有效媒体覆盖、有效组首 tag 和 RTP/RTCP 复用。没有组时只接受单个有效项；不能证明则返回 UnsupportedTransport，保守跳过新增观察，不阻断原连接。该证明位不能被规范化过程补成成功。

依据 [RFC 8843 §9.3.1](https://www.rfc-editor.org/rfc/rfc8843.html#section-9.3.1)，仅覆盖本实现选定的单组布局。更多标准允许的复杂布局尚不支持。详见离线目录 bundle-review/REVIEW.md。未运行边界或互通测试。
