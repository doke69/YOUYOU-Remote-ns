# v0.1.70–v0.1.71：离线传输优化候选

这两个版本截至本记录仅完成电脑侧编译、静态审核和打包，未安装到 Switch，不能认定解决 50 Mbps 卡顿。Lite 当前实际安装 v0.1.69；v0.1.62 仍保留为已验证流畅基线。

## v0.1.70

- 批量收包实验默认关闭，仍可显式编译开启。v69 用户反馈 CPU3 高负载与卡顿没有明显改善，不把 API 生效等同于性能提升。
- 严格组帧减少重复树查找、重复 IDR 候选扫描和一次 RTP 载荷复制；保留消息所有权及内存预算。
- 完整帧、NAL/FU、参数集、序号和恢复锚点校验保留，不把不完整参考帧送入解码器。
- 修正 MbedTLS 读取回调将请求容量误报为实际读取长度的问题。这不是 SRTP 视频逐包解密的替代。

## v0.1.71

- 在 v70 基础上独立修正 DTLS 定时器接收任务的计数配对：定时器改走预约入口，避免直接进入处理函数却仍扣减待处理计数。
- 使用原子转换合并并发预约，保留原来的握手时间、认证、排空队列和超时行为。
- 接收器继续兼容 schema16，新版本不改变诊断字段布局。

## 保留与验证限制

首页长按＋正常退出、现有配对与画质逻辑、GPU 硬件帧显示保留。没有修改频率、绑核、系统网络模块、卡分区或存档。

未运行新增测试套件，未进行这两个候选的真机性能测试。CPU3 热点、发送突发与系统网络服务成本的关系仍需证据；不能把菜单设为 50 Mbps 当成实际已稳定传输 50 Mbps。用户返回后再对照实际码率、恢复停顿、CPU3 和体感。
