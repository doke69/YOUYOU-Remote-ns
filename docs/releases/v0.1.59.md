# v0.1.59：encoded queue 突发吸收与独立数字时序

> 诊断/恢复性小版本。保留 v0.1.58 的 schema 12、YOUYOU 品牌、NACP/图标、默认码率、buffer=8ms、ready 队列4帧、skipDue/skipBound 和严格接收器 deadline/PLI 逻辑。

## 变更

- `Media::video` 的 encoded queue 保护从 **16 帧** 调整为 **32 帧 / 8MiB 总量**：
  - 单 AU 2MiB 上限仍先执行；
  - 入队前后都不能超过 8MiB；比较使用 `size > limit - queueBytes`，避免加法溢出；
  - 任一上限触发时仍执行原有“清空 queue、清 ready、请求 IDR”逻辑。
  - 目的是让 `delivery_burst` 补包突发（如24帧）在解码队列短时吸收，避免 16 帧阈值立刻破坏参考链并触发 `decoder_recovery`/等 IDR。
- 播放数字时序与 AU dump 解耦：
  - `playout_frames.csv` 的数字 trace（最多1500行）不再要求 `diag_` 或 `auDump_`；仅在 reset/析构 flush 时写文件。
  - 只含 timestamp/due/selected/reason/target 等数字与事件名，不含帧像素、账号、端点；不启用视频 dump/截图。
  - 原 `video.h264/video.h265`、`media_info.txt`、`decoded_before_display.ppm` 仍只在原 `diag_` 路径出现；`media_info` 未扩写。
- PC receiver：接受 schema 12 的 `version` 为 `0.1.58` 或 `0.1.59`；字段集合与 schema 不变。
- 无显示 target 语义修改，无 `ready` 4帧/`skipDue`/strict deadline/PLI/默认码率/buffer 修改。
