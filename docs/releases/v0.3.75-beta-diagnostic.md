# 0.3.75 Beta 连接诊断版

本地候选版，针对个别电脑停在连接建立阶段的问题；未完成真机验收。

- 补充 control_id / device_capability 控制请求包装，内外控制 ID 一致，保留此前平铺能力字段，画面尺寸/编码能力不变。ICE 会话 ID 使用服务器控制应答值；控制应答若明确属于其他 app_control_id 则拒绝，不接受错会话。
- 完整收集 Socket.IO 二进制附件，按 placeholder 索引重建消息；支持明文 SDP、base64 gzip_sdp、二进制 gzip_sdp 和明确带 0x04/gzip 头的旧附件。解压后继续走原有 SDP/编解码协商。
- 限制附件累计/重建 2MiB、SDP 解压后 1MiB；损坏、截断、CRC 错误、错附件引用明确失败，不把错误内容交给 RTC SDK。
- 连接/重连期间跳过设备列表同步刷新，避免同一工作线程阻塞接收信令，以及 loading/idle 覆盖当前会话状态；返回首页断开后可正常刷新。
- 保留阶段计时、队列压力、首个媒体/呈现提交、受限 TURN 失败恢复诊断。新增分发前事件类别、二进制附件接收及未收齐计数，便于识别 SOAC=0 的具体位置。

## 测试时核对

启动应出现 `app-start-0.3.75-beta` 和 `connection-diagnostics-0375-v1`。控制请求带 `control-request-schema-v2-compatible`。

连接时会分别记录：

1. `socket-event-packet-soac-type-*`：已经识别 SOAC 事件头；
2. `socket-binary-attachments-complete-count-*`：有二进制附件时，已收齐并重建；
3. `soac-description-format-*`：选中明文/base64 gzip/二进制 gzip 应答；
4. `soac-description-applied`：远端 SDP 已应用；
5. 原有 ICE、DTLS、SCTP、PeerConnected、首个媒体和呈现提交事件。

超时同时记录 SOAC 数、Socket.IO 包数、二进制帧数、尚缺附件数，不记录 SDP/认证值。SOAC 仍为 0 时，不能直接解释为 ICE ID 校验拒绝。

复制时退出旧程序，仅替换 `SD:/switch/UURemote-ns/UURemote-ns.nro`；保留配置、会话文件及配对。诊断 NRO 是本机 FULL 资源构建，不属于本次公开发布。

## 证据与边界

TV 3.5.0 arm64 libstreamer.so 的 DeviceCapabilityInfo 原生序列化/反序列化确认了 display_info、video_codec_capability 模型（SerializeJson 0xdb1c78，DeserializeJson 0xdb2310，SerializeSioMsg 0xe17cc8）。控制包装参考本地 Linux viewer HEAD ab5d0a6；本轮未独立还原 TV/PC 的完整 Control 序列化函数，所以采用补充包装并保留旧字段的兼容诊断策略，不声称已由 APK 完整证明本日志根因。

此版不新增固定 Offer 延迟或盲目重发，不改视频解码/播放选帧/码率策略。编译与离线测试通过不能证明特定电脑已连接成功；需要返回本版本日志后确定下一处修复。
