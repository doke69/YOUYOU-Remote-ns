# v0.1.61：实际ICE套接字缓冲回读

保留用户反馈“更流畅”的v0.1.60传输策略，仅增加数值诊断。尚未部署或取得本版真机结果。

## 背景

此前启动检查查询的是临时探测套接字。ICE依赖在真正创建UDP套接字时会请求1MiB收发缓冲，但原代码忽略设置结果，因此不能据此认定实际视频套接字获得了该大小。

## 实现

- 在libjuice的UDP套接字成功绑定时，记录两次原有缓冲设置的错误码，并分别回读 `SO_RCVBUF` / `SO_SNDBUF`。
- 不改变请求的缓冲大小，不增加或改变收发行为；不调用收包、清空队列、路由、网卡或防火墙接口。
- 固定16项进程内数值表，由短临界区保护；只在创建套接字时记录，每秒诊断发布时读取。不增加逐包处理，不保存视频或账号内容。
- 只有已选路径是UDP且本地候选为host、端口与绑定记录匹配时，才报告匹配成功；端口不匹配、NAT翻译候选或记录未找到均报告未知，不猜测缓冲值。
- 这是创建时的缓冲回读，不是实时队列占用或内核丢包计数；缓冲设置成功也不能证明Wi-Fi没有丢包。

## 实时字段

schema升级为13，四组布局和每报文1200字节上限不变。core新增：

| 字段 | 含义 |
|---|---|
| `udp_match` | 匹配实际host UDP端口的创建记录：1/0 |
| `udp_rx_bytes` / `udp_tx_bytes` | 创建时系统回读的收/发缓冲字节数；未知为-1 |
| `udp_rx_errno` / `udp_tx_errno` | 设置原有缓冲请求的错误码；0成功，-1未知 |

回读失败时缓冲大小为-1；设置成功与回读成功分别解释。电脑接收器同时接纳旧schema12的0.1.58–0.1.60与schema13的0.1.61，严格字段校验和凭据脱敏保持。

libjuice的修改保存在带原MPL-2.0声明的依赖覆盖文件及SHA256清单中，以便重建时保留。
