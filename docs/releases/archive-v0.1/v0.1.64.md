# v0.1.64：分离自定义编码上限与接收带宽反馈

## v63观察

Lite用户确认自定义50Mbps明显卡顿。约108秒观察中实际峰值29.672Mbps，RTT最高275ms，最长新画面间隔2116ms，明显缺口和RTX恢复；平均解码2.83ms，解码错误0。切回原画后首段23秒零新增缺口/NACK/RTX，延迟最高47ms。场景和运行时间并非严格实验室匹配，尚不能归因于单一环节，也不能证明实际达到50Mbps。

## 本版唯一传输实验

v63将自定义编码上限同时配置为固定REMB。依赖中的RtcpReceivingSession保存该数值，在每个发送端报告后继续上报；这不是根据当前网络测出的可用带宽。

v64保留原版Custom=6、max_custom_bitrate字段8及Mbps到bps的换算，仅阻止自定义模式发送固定REMB。保留正常RTCP报告、NACK、RTX、现有接收恢复策略。进入或离开自定义模式重连以清除旧轨道上保存的REMB；自定义档位之间继续通过既有CaptureSettings请求应用。

未修改解码、GPU显示、720p60、H265、播放缓冲、垂直同步、1MiB UDP缓冲或保护阈值。菜单沿用v63，试用仍不覆盖磁盘稳定画质配置。

## 验证与限制

下一轮同场景自定义50Mbps：targetcap=50但feedback应为0，实际码率独立观察。若没有固定REMB导致主机码率被限制，须如实记录，不能称50Mbps稳定。若卡顿改善，也仍需要区分实际流量下降与恢复逻辑改善。

本版为隔离因素的候选版本，尚未真机验证，不宣称已经解决。未运行测试套件。
