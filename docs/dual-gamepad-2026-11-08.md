# 两路手柄与模式切换排查

基线：当前 R5 源码，候选标签 `0.3.75-r6pad`。保留 TWCC-01 与 RBE 配置，TWCC-02 广告仍关闭。此功能候选没有部署或真机验证。

## 范围

- 两个 Switch 玩家位置独立转发为远端编号 0、1；支持系统识别的两只完整蓝牙手柄，以及左右单 Joy-Con。顺序来自系统配对，不强制左手柄为玩家 1。
- 提供系统手柄连接／顺序入口与两名玩家本地连接状态；仅由用户操作打开。
- 单 Joy-Con 横握映射、独立连接／发送缓存／释放／断开、按编号处理震动。
- 外接玩家 1 优先；掌机内置输入作为玩家 1 的回退，避免两种输入混入单 Joy-Con 映射。
- 未改媒体、编解码、FFmpeg、AU/AVPacket、播放选帧、原生 GPU、CPU 频率、绑核或 IPv6。

## 模式切换的静态发现

1. 原输入模式仅在内存中保存，重启会回到键鼠；候选将其纳入现有首选项的验证、保存和恢复。
2. 原等待松键使用过滤掉 Minus 的 `c.held`，长按切换时无法准确等待快捷键松开。候选使用两路真实按键，排除摇杆方向伪按键。
3. 原快捷键只适配完整手柄：单右 Joy-Con 没有 Minus，单左没有 Plus。候选统一单 Joy-Con 的本只 +/- 为短按 Start、长按本地菜单；通过菜单切换模式。
4. 长按识别改成每人独立状态，同一次持续按住只触发一次；菜单占用期间取消未完成的长按。
5. 原单个远端连接标志不适合第二只手柄；候选按两路编号保存连接状态，重连时每路更新前分别补连接消息。

以上是代码层面的发现和修正，不能认定就是用户反馈的最终根因。“模式未变化”“模式已变但 PC/游戏无输入”“重启恢复键鼠”必须分别核实。模式日志仅记录本地切换；控制通道提交成功不代表 PC 已创建或游戏已接收虚拟手柄。

### 用户补充的现象

用户进一步明确：模式提示已切换，PC 的 `joy.cpl` 中能看到 Xbox 手柄，并且属性测试页的按钮和摇杆均随 Switch 操作正常变化。

这支持该次观察中本地手柄输入已到达 Windows 测试界面，后续应针对游戏的控制器支持、读取位置和启动器输入处理排查，不能将上述快捷键或保存修正认定为该反馈的修复。尚缺游戏名称、启动方式、版本和其他控制器情况；也未确认上述观察使用的是本候选包，不能据此把本候选标成真机验收通过。

## 离线与真机边界

离线检查覆盖横握坐标/按键、两人独立长短按、菜单取消、持续按住不重复、计时回绕，震动消息编号 0/1 与非法编号拒绝，以及既有输入准入测试。完整编译、产物与保护文件结果以 `C:/uu/releases/diagnostics/dual-gamepad-20261108/REVIEW.md` 为准。

真机应按以下顺序验证：

1. 单完整手柄的默认键鼠、长按 Minus 切换、Plus 打开菜单及首页长按退出。
2. 退出重启后恢复输入模式；切换时按住其他键，松开后恢复输入且没有残留按键。
3. 系统配对两只完整蓝牙手柄，PC 同时出现两个虚拟 Xbox 手柄；双人游戏分别加入，输入互不串路。
4. 拆分 Joy-Con，核对两边横握摇杆上下左右、四面键、SL/SR、扳机和本地菜单。
5. 分别拔除/关机任一手柄、重新连接、调整顺序、打开菜单、切换模式、断开串流；检查另一玩家、释放状态及震动归属。
6. 标准 Switch 掌机、底座和 Lite 外接手柄分别验证；系统配对界面及横握布局尚未观察。

保持旧 R5 NRO 以便回退；未上传认证材料或产物。
